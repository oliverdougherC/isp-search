# ISP Search — Address-to-Provider Candidate Discovery: Evidence-Backed Decision Matrix

Prepared: 2026-09-02. All web sources were fetched on 2026-09-02 unless noted. Facts are attributed to the URL where they were read. Anything not confirmed from a primary/official page is marked **UNVERIFIED**. No FCC map backend endpoints were called, probed, or reverse-engineered; only documentation, Swagger, terms pages, and the public map's About/Data Download pages were read. No real residential address was submitted anywhere or written here.

Access notes affecting evidence quality:

- `www.fcc.gov` and `broadbandmap.fcc.gov` returned HTTP 403 ("Access Denied", Akamai) to both HTTP fetch tools; those pages were read via a normal browser session instead. `help.bdc.fcc.gov` article bodies were read through the Zendesk help-center public JSON API (`/api/v2/help_center/en-us/articles/{id}.json`), which returns the same article content with an `updated_at` timestamp.
- Two Box-hosted FCC PDFs ("Public Data API Specifications", 24 pp., and "Broadband Map Data Downloads" spec, 81 pp.) rendered only as an image viewer and could not be text-extracted in this session. Their contents are marked UNVERIFIED where relevant; the Public Data API **Swagger YAML** (same Box folder) _was_ fully read.
- The URL `https://www.fcc.gov/general/fcc-website-terms` returns "Page Not Found". The FCC's live footer links are "Website Policies & Notices" (`/general/website-notices`), "Privacy Policy" (`/general/privacy-policy`), and the developer "API Terms of Service" (`/reports-research/developers/api-terms-service`); those were read.

## 1. Documented FCC public APIs (BDC "Public Data API")

**Where it is documented.** The BDC Help Center "Key Reference Documents" page (updated 2026-05-06) links "Public Data API Swagger (YAML)" → `https://us-fcc.box.com/v/bdc-public-data-api-swagger` and "Public Data API Specifications" → `https://us-fcc.box.com/v/bdc-public-data-api-spec`. It also links the "Provider Response API Swagger" (filer-side) and "Broadband Map Data Downloads" spec (`https://us-fcc.box.com/v/bdc-data-downloads-output`). [Source: https://help.bdc.fcc.gov/hc/en-us/articles/6789299021723-Key-Reference-Documents]

**What the Swagger says (file `bdc-public-data-api-swagger.yaml`, Swagger 2.0, info.version "1.2.0", title "BDC Public Data").**

- `host: broadbandmap.fcc.gov`, `basePath: /api/public`, `schemes: https`; `termsOfService: https://www.fcc.gov/reports-research/developers/api-terms-service`; contact `BroadbandDataInquiries@fcc.gov`.
- Authentication: every data endpoint requires two **headers**: `username` ("Username from FCC User Reg") and `hash_value` ("Hash value token associated with username"). (The web-search summary of the spec PDF states an active FCC User Registration account is required; the PDF itself was not readable here — **UNVERIFIED** beyond the Swagger header definitions.)
- The complete list of documented paths:
  1. `GET /` — status check ("Returns current status of the app if it is available or not").
  2. `GET /map/listAsOfDates` — "Provides a listing of as of dates available for each data type". Returns `{data_type, as_of_date}` rows.
  3. `GET /map/downloads/listAvailabilityData/{as_of_date}` — "Provides a full listing of all coverage files that are available for download for a given as of date". Optional query filters: `category` ∈ {Summary, State, Provider}; `subcategory` ∈ {"Summary by Geography Type - Census Place", "Summary by Geography Type - Other Geographies", "Provider Summary by Geography Type", "Provider Summary", "Provider List", "Location Coverage", "Hexagon Coverage", "Raw Coverage", "Supporting Data"}; `technology_type` ∈ {Fixed Broadband, Mobile Broadband, Mobile Voice}; `speed_tier` ∈ {35/3, 7/1}. Returns file metadata: `file_id, category, subcategory, technology_type, technology_code, technology_code_desc, speed_tier, state_fips, state_name, provider_id, provider_name, file_type, file_name, record_count`.
  4. `GET /map/downloads/listChallengeData/{as_of_date}` — listing of challenge files.
  5. `GET /map/downloads/downloadFile/{data_type}/{file_id}` and `.../{file_id}/{file_type}` — "Allows users to download availability and challenge data based on the ID and type of the file" (binary).
  6. `GET /fundingmap/downloads/listFundingData` and `GET /fundingmap/downloads/downloadFile/{file_id}` — Broadband Funding Map file listing/download.
- **No documented public endpoint accepts a street address, latitude/longitude, or a `location_id` and returns providers.** The API is a file-catalog and bulk-download interface only. [Source: Swagger YAML read at https://us-fcc.app.box.com/v/bdc-public-data-api-swagger]
- Rate limits: not stated in the Swagger. **UNVERIFIED** (may be in the spec PDF).

**FCC API Terms of Service (applies per the Swagger `termsOfService`).** Key language: "You may use any FCC API to develop a service or service to search, display, analyze, retrieve, view and otherwise 'get' information from FCC data." Attribution: "All services which utilize or access the API should display the following notice prominently within the application: 'This product uses the FCC Data API but is not endorsed or certified by the FCC'." "Right to Limit: Your use of the API may be subject to certain limitations on access, calls, or use ... If the FCC reasonably believes that you have attempted to exceed or circumvent these limits, your ability to use the API may be permanently or temporarily blocked. The FCC may monitor your use of the API ..." Provided "as is"; FCC may terminate access "at any time for any other reason in its sole discretion"; user indemnifies FCC. [Source: https://www.fcc.gov/reports-research/developers/api-terms-service]

**Assessment.** Usable only as a scripted way to enumerate "as of" dates and pull the same files available on the Data Download page. Not a lookup service.

## 2. Downloadable BDC fixed-availability datasets

**What is on the Data Download page (read 2026-09-02).** Tabs: By State, By Provider, Challenges. "Availability Data As Of" selector lists: Dec 31, 2025 (latest); Jun 30, 2025; Dec 31, 2024; Jun 30, 2024; Dec 31, 2023; Jun 30, 2023; Dec 31, 2022; Jun 30, 2022. Page shows "Last updated 8/18/26". Summary downloads: Provider List; Provider Summary by Geography Type; Provider Summary – Fixed Broadband; Provider Summary – Mobile Broadband; Fixed Broadband Summary by Geography Type (State, County, Congressional District, Tribal Areas, CBSA (MSA)) plus Census Place (by state); Mobile equivalents. Links at top: "Data Spec. for BDC Public Data Downloads" and "BDC Public Data API Specifications". [Source: https://broadbandmap.fcc.gov/data-download?version=dec2025]

**What the files contain / keying.** FCC: "The FCC's National Broadband Map allows users to download data reported by providers on the broadband serviceable locations (or BSLs) they serve and the type of service offered at each BSL. These downloadable data are available by Location ID, which is the unique identifier for each BSL on the map and in the Fabric. To obtain more information about the location beyond its Location ID, such its address, geographic coordinates, and building type, users will need to obtain access to the Fabric." [Source: https://help.bdc.fcc.gov/hc/en-us/articles/10419121200923-How-Entities-Can-Access-the-Location-Fabric, updated 2025-03-03]

The per-record content mirrors what filers submit in the location-list format: `provider_id` (6-digit FCC code), `brand_name`, `location_id` ("A unique identifier for the location served. Each Location ID is a 10-digit number starting with one billion"), `technology` (10 Copper, 40 Coax/HFC, 50 FTTP, 60 GEO sat, 61 NGSO sat, 70 Unlicensed FW, 71 Licensed FW, 72 Licensed-by-rule FW, 0 Other), `max_advertised_download_speed`, `max_advertised_upload_speed`, `low_latency` (≤100 ms at 95th percentile), `business_residential_code` (B/R/X). "A location can be included multiple times" (one record per technology per provider). [Source: https://help.bdc.fcc.gov/hc/en-us/articles/5291539645339-How-to-Format-Fixed-Broadband-Availability-Location-Lists, updated 2025-07-31] The exact column list of the _public download_ files (e.g., whether census block or H3 columns are included) is in the 81-page Box spec PDF that could not be text-extracted: **UNVERIFIED**. The Swagger's `subcategory` enum does include "Location Coverage", "Hexagon Coverage", and "Raw Coverage", indicating both location-keyed and hexagon-keyed fixed files exist.

**Meaning of a record.** Providers report locations "to which they either have a customer or could perform a standard broadband installation", i.e., service initiation "within 10 business days of a request ... with no charges or delays attributable to the extension of the network". Fixed wired filers must respect maximum buffer distances; fixed wireless polygons must use propagation modeling with stated parameters. [Source: https://help.bdc.fcc.gov/hc/en-us/articles/5290946484763-Fixed-Broadband-Availability-Data-Overview, updated 2025-02-28]

**Cadence / vintage.** "All providers must report data as of June 30 (due September 1) and December 31 (due March 1) each year." [Sources: https://help.bdc.fcc.gov/hc/en-us/articles/13532984820379-What-s-on-the-National-Broadband-Map (updated 2025-11-25); https://broadbandmap.fcc.gov/about] The eighth filing window (data as of Dec 31, 2025) opened Jan 2, 2026 with filings due Mar 2, 2026. [Source: DA 25-1080, https://docs.fcc.gov/public/attachments/DA-25-1080A1.pdf, released Dec 18, 2025] The Dec 31, 2025 vintage is the "latest" on the download page as of 2026-09-02. Note the Fabric FAQ: "Location IDs will remain constant within each version of the Fabric" but "There are some circumstances ... when a new location ID will be generated" — availability files must be paired with the matching Fabric version.

**File sizes.** **UNVERIFIED** (not shown on the page text; not downloaded in this session). The Fabric FAQ notes Fabric county files can exceed Excel's 1,048,576-row limit, implying multi-GB national scale.

**Terms / attribution.** "Broadband availability data from the BDC, and data from the U.S. Census Bureau that are presented on this site, are offered free and not subject to copyright restriction. Data and content created by government employees within the scope of their employment are not subject to domestic copyright protection under 17 U.S.C. § 105." "While not required ... we ask that you provide proper attribution of the data. Examples include: Source data: FCC Broadband Data Collection; Map layer based on FCC BDC." Critically: "CostQuest Associates, Inc. and its third-party licensors, as applicable, own all right, title, and interest, including all intellectual property rights, in and to the data for locations reflected in the Fabric (including the Location ID, latitude and longitude, address, unit count, and building type code for each location in the Fabric)." [Source: https://broadbandmap.fcc.gov/about, "License and Attribution"]

**Negative evidence.** For a _known_ `location_id`, absence of any record in the fixed availability files for a vintage means no provider reported service at that BSL (the map renders such points red: "Red locations have no reported internet services available" [https://help.bdc.fcc.gov/hc/en-us/articles/10467446103579]). This is meaningful negative evidence _only if you can lawfully map an address to its location_id_, which requires the Fabric (Section 3).

## 3. Location Fabric licensing

**What it is.** "The Broadband Serviceable Location Fabric (Fabric) is a dataset of all locations in the United States and its Territories where fixed broadband internet access service is or could be installed." Produced under FCC contract by CostQuest Associates. Delivered "as a ZIP archive consisting of multiple files in a Comma Separated Values (CSV) format. Each file contains location records for an entire county", including "a secondary address file". Data dictionaries and methods manuals are public (Box links). [Source: https://help.bdc.fcc.gov/hc/en-us/articles/5375384069659-What-is-the-Location-Fabric, updated 2025-07-31]

**Fabric contents relevant to address search / MDU.** Each BSL is "a single point ... within the footprint of a structure" with a unique Location ID. MDUs: "In the case of multiple housing units within a single structure on a single parcel, the location will have a single entry or record in the Fabric ... The record for that BSL in the Fabric contains a count of the individual units within that building." Addresses: "some locations in the Fabric do not have addresses, and some have addresses that do not, or cannot, receive U.S. Mail"; there is an "address confidence" field and "interpolated" addresses; most are CASS-certified USPS-standardized. [Source: https://help.bdc.fcc.gov/hc/en-us/articles/7412732399003-Fabric-FAQs, updated 2025-07-31]

**Address-to-location_id matching guidance (FCC).** "Joining your location data to locations in the Fabric based on the relative proximity of the locations offers the best chance of success. Relying solely on address matching or other non-geospatial processes is likely to produce poor and inaccurate results." Recommended proximity 10–15 m. Also warns that "relying on commercially available geocoders" without geospatial analysis can mislead. [Source: https://help.bdc.fcc.gov/hc/en-us/articles/48535890138907-How-to-Align-Your-Location-Data-to-the-Broadband-Serviceable-Location-Fabric, updated 2026-08-04]

**License tiers (FCC-sponsored, no cost).**

- "There is no cost. Accessing the Fabric is free. However, entities must first sign a license agreement with CostQuest Associates". [Fabric FAQs]
- FCC licenses are "Tiers 1, 2, 3, & 4" and "are specific to FCC Broadband Data Collection (BDC) purposes ... for FCC BDC purposes only." Tier 2 = broadband service providers; Tier 4 = "entities that are not governments, tribes or ISPs". (Tier 1 and Tier 3 definitions were not stated in the fetched sources: **UNVERIFIED**.) "No. The FCC Licensed Materials are only for FCC BDC purposes ... Use of FCC Licensed Materials for purposes other than FCC BDC purposes is a violation of the FCC License Agreement." "FCC Tier 2 Licensees are prohibited from using Fabric data for any other purposes beyond their participation in the BDC, including commercial and non-commercial uses or any publication." [Source: CostQuest Federal Program Licensing FAQ (2024), https://www.costquest.com/wp-content/uploads/2024/05/CostQuest-Federal-Program-Licensing-FAQ_2024.pdf]
- **Tier 4 (exact permitted purposes, FCC wording):** "There are two Tier 4 Fabric License Agreements, the Standard Agreement and the Research License. The Tier 4 Standard Agreement supports the filing of BDC challenges by entities not covered under another Tier Agreement ... The Standard Agreement can only be used for the purpose of generating challenge and crowdsource data as part of the Broadband Data Collection. The Tier 4 Research License additionally supports non-commercial academic or public-policy research directly related to broadband availability." Process: FRN in CORES (entity type, not "Individual") → BDC system → select "Obtain a Fabric License" → CostQuest help desk Tier 4 Submission form (must state "Summary information on how the requested Fabric data may be used for BDC or research purposes") → e-signed license → data link. [Source: https://help.bdc.fcc.gov/hc/en-us/articles/10419121200923-How-Entities-Can-Access-the-Location-Fabric, updated 2025-03-03]
- "Can I use the Fabric data to create mailing lists, marketing campaigns, or network plans? No. The use of the Fabric dataset is limited to the Permitted Uses described in the License Agreement with CostQuest." [Fabric FAQs]
- **Conclusion on a public consumer comparison product:** a commercial/public consumer product is _not_ within the Tier 4 Standard purpose (BDC challenge/crowdsource generation) nor the Tier 4 Research purpose (non-commercial research). Using no-cost Fabric data to power ISP Search would violate the license as described.

**NTIA tiers (A–E), for completeness.** No-cost, BEAD-oriented; "distinct from the CostQuest licenses issued in support of the FCC's Broadband Data Collection program"; Tier E was for BEAD challengers and "terminated 12/31/2024" per CostQuest's FAQ page summary. Tier C licensees may publish subsets of location_ids and online maps that prevent "bulk extractions of attribute-level data". Not applicable to a private consumer product. [Sources: https://broadbandusa.ntia.gov/policies/CostQuest-Licensing; https://www.costquest.com/broadband-serviceable-location-fabric/fabric-faq/]

**Commercial licensing (CostQuest / TrueVerra).**

- CostQuest's Fabric page: no-cost "Federal Programs" path vs "Enhanced/Commercial: Available through TrueVerra for internal use beyond government reporting". Current Fabric noted as **Version 9**. Related products: "ServiceLandscape Data", "NetworkPlan Data", APIs via developer portal. [Source: https://www.costquest.com/broadband-serviceable-location-fabric/]
- TrueVerra ServiceLandscape: "Broadband coverage, competition, and federal funding intelligence at the address-level", CSV/GeoPackage, lists provider name and technology per BSL, sourced from FCC National Broadband Map. [Source: https://www.trueverra.io/broadband-fabric-service-landscape-data] FAQs: commercial licenses allow "using the data for internal business purposes"; standard term "12 months"; "further data updates to the fabric will not be available during the year licensing term" unless arranged; **no pricing published**; public/consumer-facing display is not addressed. [Source: https://www.trueverra.io/frequently-asked-questions/servicelandscape-data]
- The CostQuest `truverra` redirect from costquest.com resolved to a "broken-links" page; TrueVerra was reached at trueverra.io directly.
- CostQuest APIs (apidocs.costquest.com, developer.costquest.com): `fabricext/match` (address → `location_id`, similarity score, lat/lon; "is not a geocoder ... only locations within the Fabric can be matched to"; batch of 10 per POST; preview since 2025-08-07, rule version 2 since 2025-09-06), `fabricext/locate` (lat/lon → `location_id` with match type), `coverage/bdcfixed` (`location_id` → provider name, technology code, speeds, latency flag; "does not accept latitude/longitude, addresses"; "updated every 6 months and is synchronized with the FCC Broadband Data Fabric Releases"), `coverage/vintages`. Changelog: 2026-06-27 "The data behind the coverage API was updated to reflect the `202512` BDC data release" and "Initial Location data is available for the `202606` vintage." Auth: `apikey` header; OIDC account; credit-based quotas; 429 with `Retry-After`; rate limits per minute; tier and per-endpoint credit tables render **empty** on the docs pages (**UNVERIFIED** pricing). The checkout calculator shows examples "200,000 locations → $5,000" and "200,000 address matches → $5,000" (arithmetically $0.025/record at that volume — computed here, not stated). CostQuest's website Terms & Conditions (effective March 12, 2025) prohibit "reproduce, distribute, modify, create derivative works of, publicly display ... any of the material on our Website"; **API-specific data-use terms were not found publicly** — consumer-facing display rights are **UNVERIFIED** and would need a negotiated agreement. [Sources: https://apidocs.costquest.com/, /guides/match/, /guides/fabricext/, /guides/coverage/, /tiers/, /credits/, /authentication/; https://myaccount.costquest.com/apiCheckout/; https://www.costquest.com/legal/terms-conditions/]

**Redistribution / derivative-data restrictions (FCC-path licenses).** Only `location_id` may be shared between licensees in challenge contexts — "not addresses, coordinates, or other attributes"; Tier 2 licensees may share only with other Tier 2 licensees. [CostQuest Federal Program Licensing FAQ; CostQuest Fabric FAQ]

**Current version / vintage.** "A new version ... is released for the opening of each new biannual filing round ... on or around June 30 and December 31 of each year"; "the December 2024 version of the Fabric (also referred to as Fabric Version 6)". [Source: https://help.bdc.fcc.gov/hc/en-us/articles/11749189297947-Which-Version-of-the-Fabric-Should-I-Use, updated 2025-03-31] CostQuest's July 31, 2026 report cites "Location Fabric Versions 7 and 8 (June 2025 through December 2025)". [Source: https://costquest.substack.com/p/broadband-in-america-report-analysis] DA 25-1080 references the "December 2025 Fabric" and "the next update of the Fabric in June 2026". CostQuest's site says Version 9 is current and its API changelog shows the `202606` vintage from 2026-06-27. **Inference (not stated verbatim in any single source): Version 9 = June 2026 Fabric; Version 8 = December 2025 (pairs with the "Dec 31, 2025" availability data currently on the map).**

## 4. Undocumented FCC map implementation endpoints

- The FCC's _only_ documented public API surface for the map is the Swagger in Section 1 (`/api/public/...`, file catalog and download). The map UI's "Search by Address", "Location Summary", "Provider Detail", and "Area Summary" features are described in the help center as **interactive site features**, not as an API. [Sources: https://help.bdc.fcc.gov/hc/en-us/articles/10467446103579-How-to-Use-the-FCC-s-National-Broadband-Map; https://broadbandmap.fcc.gov/about] Any endpoints the map's front end calls to power those features are therefore **not a documented API**, carry no published contract, version, SLA, or rate-limit policy, and may change or be blocked without notice. They were not called, inspected, or probed in this research.
- **Terms.** No fcc.gov page found states an explicit scraping/automated-access policy for the map site. The "Website Notices" page covers accessibility, PRA, Privacy Act, vulnerability disclosure, and maintenance windows only. [Source: https://www.fcc.gov/general/website-notices] The API Terms of Service (Section 1) reserve a "Right to Limit" and the ability to block users who "attempt to exceed or circumvent these limits", and state the FCC "may monitor your use of the API". A web-search snippet of the legacy `wireless.fcc.gov/webpolicies.html` page states the site "may be used only for authorized purposes" and that "unauthorized attempts to upload information or change information on FCC servers are strictly prohibited" — **UNVERIFIED** (page not fetched directly).
- **Rights problem independent of terms.** Address search on the map returns Fabric-derived attributes (address, coordinates, unit count, building type), which per the map's own About page are CostQuest's intellectual property and are licensed to third parties "at no cost for purposes of their participation in the FCC's Broadband Data Collection" — not for a commercial consumer product. Mining those attributes via the map UI would sidestep the license regime in Section 3.
- **Conclusion:** not a lawful production basis. Do not build on it.

## 5. Area-level FCC evidence usable without the Fabric

**Available today (BDC, public domain).**

- "Fixed Broadband Summary by Geography Type": State, County, Congressional District, Tribal Areas, CBSA (MSA), and Census Place — served-units percentages and similar summaries. "Provider Summary by Geography Type" and "Provider List" (provider_id ↔ brand). "Hexagon Coverage" files exist per the Swagger subcategory enum (H3 hexagons; resolution not confirmed here — the FCC help center describes mobile files as H3; for fixed files this is **UNVERIFIED**). Per-provider per-state "Location Coverage" files list `location_id`s served (usable for counting a provider's presence in a state/county only if the file also carries an area key — **UNVERIFIED**, see Section 2). [Sources: https://broadbandmap.fcc.gov/data-download?version=dec2025; Swagger YAML]
- Map UI features "Provider Detail" (compare up to three providers' footprints) and "Area Summary" / "Area Comparison" (top-10 lists with downloadable full lists). [Source: https://help.bdc.fcc.gov/hc/en-us/articles/10467446103579]
- **Precision:** area (county/place/CBSA/hex), not location. Not MDU-aware.
- **Negative evidence:** weak but nonzero. If a provider reports _no_ locations in a county/place for the current vintage, it is reasonable evidence that the provider does not offer mass-market fixed service there as of that date. Presence in an area says nothing about a specific address. The FCC's own caution (from the Form 477 page) applies by analogy: a provider present in an area "may not necessarily offer that service everywhere".

**Form 477 legacy deployment data.** Fixed providers filed "lists of census blocks in which they can or do offer service to at least one location". The latest nationwide dataset is data as of **December 31, 2021** (Version 1, revisions through 08/30/22, released 12/29/2022). FCC note: "a list of providers deployed in a census block does not necessarily reflect the number of choices available to any particular household or business location in that block". Page last updated Dec 29, 2022. [Source: https://www.fcc.gov/general/broadband-deployment-data-fcc-form-477] "Broadband providers are no longer required to file broadband deployment information using FCC Form 477" (subscription/voice data still filed in the BDC system). [Source: DA 25-1080, n.2] **Status: legacy; stale by ~4.5 years; census-block precision; superseded by BDC.** Not recommended except as historical context.

## 7. Bounded launch-market registry (Route C)

**Design.** A hand-maintained, versioned JSON/YAML list per named launch metro (e.g., a few CBSAs) of plausible mass-market fixed providers, each with: brand, FCC `provider_id` (from the public "Provider List" file), technologies reported in that CBSA/county (from "Provider Summary by Geography Type"), the provider's **official** availability-check page URL, and a `last_reviewed` date. Candidate surfacing = "these providers report service somewhere in your county/metro as of {BDC vintage}; confirm at the provider or on the FCC map." Every result deep-links to the FCC National Broadband Map home page (user performs the address search on the FCC site; do **not** pass the address in a query string).

**Evidence used, all lawful:** BDC area summaries and provider list (public domain; attribution requested), provider names used nominatively, official provider footprint pages read manually (no automated querying of provider serviceability tools).

**Precision:** county/CBSA/place. MDU: none. **Negative evidence:** none — the registry can never say "no one serves you"; copy must say so.

**Maintenance burden:** two scheduled refreshes per year keyed to BDC releases (the map's Dec-31 data appeared with "Last updated 8/18/26"; June-30 data historically lands ~Nov–Dec), plus ad-hoc edits for launches/withdrawals. Per metro, expect a few hours per refresh to reconcile the BDC provider list against the registry (the BDC provider count for the area is a natural completeness check: any provider with material served-unit share in the area but absent from the registry is a gap). Risk of silent staleness is mitigated by displaying the vintage and `last_reviewed` on every result.

**Honesty of completeness claims:** must be explicit — "Candidates, not a serviceability check"; "Based on FCC BDC data as of {date}; providers may not serve every address"; and the absence of negative evidence must be stated. Because the FCC data is location-level in truth but only area-level in what we can lawfully join without a Fabric license, the product should not present provider _counts_ as if they were address-specific.

## Recommendation

**Can exact nationwide address-level candidate discovery be supported today on a lawful production basis? No — not from free/public sources, and not yet from a verified commercial basis.**

Reasons, each tied to evidence above:

1. The FCC's documented public API contains no address, lat/lon, or `location_id` lookup; it is a file catalog (Section 1).
2. BDC availability downloads are keyed to `location_id`; the FCC states that resolving anything beyond the ID (address, coordinates, building type) "will need ... access to the Fabric" (Section 2).
3. The no-cost Fabric licenses available to a non-ISP, non-government entity (Tier 4 Standard/Research) are limited to BDC challenge/crowdsource generation and non-commercial research; a public consumer comparison product is outside those purposes, and CostQuest states FCC-licensed materials "cannot be used for purposes outside of that License Agreement" (Section 3). CostQuest owns the Fabric attributes (map About page).
4. The map's front-end endpoints are not a documented API; using them would also route around the Fabric license (Section 4).
5. Commercial feeds exist but do not yet clear the bar: BroadbandMap.com is hex-cell (not address) with ephemeral-use-only terms and unstated vintage; CostQuest's APIs are the right shape but pricing tables are unpublished and consumer-facing display rights are unverified (Section 6).

**Recommended first public beta: Route C (bounded launch-market registry)** with:

- area-level BDC evidence as supplementary "candidate" evidence (Provider Summary by Geography Type / Fixed Broadband Summary by Geography Type for the launch CBSAs/counties, current vintage Dec 31, 2025), displayed with vintage and the requested FCC attribution;
- a deep link to the FCC National Broadband Map (home page; user types the address there — never place the address in a URL);
- explicit copy: candidates only, no negative evidence, provider confirms serviceability;
- a versioned registry with `last_reviewed` per entry and a refresh calendar tied to BDC releases.

**To graduate to Route A (licensed Fabric + BDC join, address-level, with negative evidence):**

- Obtain a **commercial** Fabric license from CostQuest/TrueVerra whose permitted uses expressly cover public, consumer-facing display of matched BSL attributes and derived "served / not served" statements; confirm term, update rights during term (TrueVerra FAQ says updates are not included by default), redistribution/derivative-data clauses, and required notices. Qualified legal review required.
- Build geospatial (not address-only) matching per FCC guidance (10–15 m proximity; handle no-address/interpolated/low-confidence records; MDU = single BSL with unit count).
- Pair each BDC vintage with its Fabric version (v8 ↔ Dec-2025 data; v9 ↔ Jun-2026 data, inferred) and handle `location_id` retirements.
- Operate bulk ingestion from the Data Download page or the Public Data API (FCC User Registration credentials; display the FCC API attribution notice if the API is used).

**To graduate to Route B (commercial feed):**

- CostQuest APIs: obtain written API data-use terms permitting consumer display and reasonable caching; get the tier/credit price sheet; validate match precision and MDU behavior on synthetic/test addresses only; budget on the $5,000-per-200k-records calculator example pending a quote.
- BroadbandMap.com: only if hex-level precision is acceptable for candidate discovery; negotiate a non-standard plan if any persistence beyond "short-lived operational caching" is needed; obtain the BDC vintage they serve in writing.
- Either way, keep the Route C registry as the fallback and the FCC deep link as the authoritative confirmation path.

## FCC 26-48 (Broadband Labels) — status of the machine-readable label file requirement

Reported strictly from the sources:

- **Order:** "Empowering Broadband Consumers Through Transparency" / "Delete, Delete, Delete", CG Docket No. 22-2, GN Docket No. 25-133, Report and Order, **FCC 26-48, Adopted: July 22, 2026; Released: July 23, 2026.** [Source: https://docs.fcc.gov/public/attachments/FCC-26-48A1.pdf]
- **Machine-readable file:** "We eliminate the requirement that providers make the contents of labels available separately in a machine readable spreadsheet file format hosted at a dedicated URL" (para. 32). Footnote 83: "The eliminated requirement is for a separately hosted machine-readable data file in a format such as CSV, JSON, or XML, designed primarily for bulk data aggregation by third parties." Para. 34: "there is no record evidence that any third parties have used machine-readable label content to develop pro-consumer tools." Appendix A: § 8.1(a)(3) "[Removed and Reserved]" (also (a)(5) and (a)(7)).
- **Effective dates (ordering clause para. 61):** amendments to § 8.1(b) "SHALL BE EFFECTIVE 30 days after publication in the Federal Register"; amendments to § 8.1(a) "will not become effective until the Office of Management and Budget completes review of any information collection requirements ... The Commission directs the Consumer and Governmental Affairs Bureau to announce the effective date of the amendments to section 8.1(a) of the rules by subsequent Public Notice."
- **Federal Register:** final rule published **August 13, 2026**, 91 FR 52251, document 2026-16503. "DATES: Effective September 14, 2026, except for instruction 3 (§ 8.1(a)), which is delayed indefinitely. The Commission will publish a document in the Federal Register announcing the effective date." [Sources: https://www.federalregister.gov/api/v1/documents/2026-16503.json; full text XML https://www.federalregister.gov/documents/full_text/xml/2026/08/13/2026-16503.xml. Note: the human-readable page at /documents/2026/08/13/2026-16503/... redirected to an "unblock" page for automated fetch; the API and XML were used instead. The URL slug in the task ("empowering-consumers-to-choose-the-broadband-services-they-need") differs from the actual slug "empowering-broadband-consumers-through-transparency"; same document number.]
- **Later public notice:** As of 2026-09-02, no CGB Public Notice announcing the § 8.1(a) effective date was found (searches of fcc.gov and the Federal Register). The fcc.gov "CGB Announces Compliance Dates for Broadband Label Rules" document is **DA 23-943 (Oct 10, 2023)** and concerns the 2024 compliance dates, not FCC 26-48. The FCC Broadband Labels page (updated July 23, 2026) says the July 2026 Order "will modify the Broadband Label rules". [Sources: https://www.fcc.gov/document/cgb-announces-compliance-dates-broadband-label-rules; https://www.fcc.gov/broadbandlabels]
- **Net status:** the deletion of the machine-readable-file requirement (§ 8.1(a)(3)) is adopted but **not yet effective**; § 8.1(a) as currently codified remains in force until OMB completes PRA review and CGB announces an effective date. The § 8.1(b) definitional amendments take effect September 14, 2026. Product implication: machine-readable label files should be treated as a disappearing input, not a foundation.
